useContext হলো React-এর একটি গ্লোবাল স্টেট শেয়ারিং হুক। প্রজেক্টে Prop Drilling সমস্যা সমাধান করতে এবং অ্যাপ্লিকেশনের গ্লোবাল ডেটা (যেমন: Theme, Authentication, Cart State, Language Preference) অনায়াসে যেকোনো লেভেলের কম্পোনেন্টে অ্যাক্সেস করতে useContext ব্যবহৃত হয়।

১.  useContext কী এবং কেন? (Core Concept)
    ১.  সমস্যা: Prop Drilling
        ধরো, তোমার টপ-লেভেল কম্পোনেন্ট App-এ একটি user অবজেক্ট আছে, যা ৫ নম্বর লেভেলের চাইল্ড কম্পোনেন্ট UserProfile-এ প্রয়োজন। সাধারণ নিয়মে না চাইলেও মাঝখানের ৩টি কম্পোনেন্টের মধ্য দিয়ে Prop হিসেবে এই ডেটা পাস করে যেতে হয়। একেই বলে Prop Drilling।

    ২.  সমাধান: useContext
        useContext একটি Teleportation System-এর মতো কাজ করে। এটি একটি গ্লোবাল ডেটা সেন্টার বা "Context" তৈরি করে, যেখান থেকে যেকোনো চাইল্ড কম্পোনেন্ট সরাসরি ডেটা টেনে (Subscribe) নিতে পারে—মাঝখানের কম্পোনেন্টগুলোকে স্পর্শ না করেই।

২.  useContext বাস্তবায়নের ৩টি ধাপ (3 Steps Implementation)
    useContext সঠিকভাবে বাস্তবায়নের জন্য ৩টি কাজ করতে হয়:
        ১.  createContext: Context অবজেক্ট তৈরি করা।
        ২.  Provider: ট্রি-এর ওপরের লেভেলে ডেটা সরবরাহ (Provide) করা।
        ৩.  useContext: চাইল্ড কম্পোনেন্টে বসে সেই ডেটা পড়া/গ্রহণ (Consume) করা।

৩.  প্রোডাকশন আর্কিটেকচার (Best Practice Pattern)
    বাস্তব প্রজেক্টে সরাসরি ফাইলজুড়ে useContext না লিখে একটি Custom Provider Component এবং Custom Hook প্যাটার্ন ব্যবহার করা হয়।

    রিয়েল প্রজেক্ট উদাহরণ: Auth Context (src/context/AuthContext.jsx)
        JavaScript
        import React, { createContext, useContext, useState } from 'react';

        // ১. Context তৈরি
        const AuthContext = createContext(null);

        // ২. Custom Provider Component
        export const AuthProvider = ({ children }) => {
            const [user, setUser] = useState(null);

            const login = (userData) => {
                setUser(userData);
            };

            const logout = () => {
                setUser(null);
            };

            return (
                <AuthContext.Provider value={{ user, login, logout }}>
                {children}
                </AuthContext.Provider>
            );
        };

        // ৩. Custom Hook (নিরাপত্তা ও সহজ ব্যবহারের জন্য)
        export const useAuth = () => {
            const context = useContext(AuthContext);
            if (!context) {
                throw new Error('useAuth must be used within an AuthProvider');
            }
            return context;
        };

    =>  অ্যাপে যুক্ত করার নিয়ম (src/App.jsx):
        JavaScript
        import { AuthProvider } from './context/AuthContext';
        import Navbar from './components/Navbar';
        import UserProfile from './components/UserProfile';

        export default function App() {
            return (
                <AuthProvider>
                <Navbar />
                <UserProfile />
                </AuthProvider>
            );
        }

    =>  যেকোনো চাইল্ড কম্পোনেন্টে ব্যবহার (src/components/UserProfile.jsx):
        JavaScript
        import React from 'react';
        import { useAuth } from '../context/AuthContext';

        export default function UserProfile() {
            // সরাসরি কাস্টম হুক ডেকে গ্লোবাল স্টেট ও মেথড ব্যবহার
            const { user, logout } = useAuth();

            if (!user) return <p>Please log in.</p>;

            return (
                <div>
                <h2>Welcome, {user.name}!</h2>
                <button onClick={logout}>Log Out</button>
                </div>
            );
        }

৪.  useContext-এর পারফরম্যান্স সমস্যা ও সমাধান (Critical Interview Topic)
    ইন্টারভিউতে সবচেয়ে বেশি ট্রিকি প্রশ্ন করা হয় useContext-এর Re-render মেকানিজম নিয়ে।

    সমস্যা: Unnecessary Re-renders
        যখনই Context.Provider-এর value আপডেট হয়, সেই Context ব্যবহার করছে এমন সবকটি Consumer Component রি-রেন্ডার হয়।
        এমনকি কোনো কম্পোনেন্ট যদি Context-এর শুধু user প্রপার্টি ব্যবহার করে আর আপনি theme চেঞ্জ করেন, তবুও ওই কম্পোনেন্টটি Re-render হবে!

    রিয়েল প্রজেক্টের সমাধানসমূহ:
        1.  Split Contexts (কনটেক্সট ভাগ করা):
            একটি বড় Context-এ সব ডেটা না রেখে আলাদা করে ছোট Context তৈরি করা।
            (যেমন: ThemeContext এবং AuthContext আলাদা রাখা)।

        2.  Memoizing Value (useMemo):
            Provider-এর value অবজেক্টকে useMemo দিয়ে র‍্যাপ করা, যাতে অহেতুক নতুন অবজেক্ট রেফারেন্স তৈরি না হয়।

            JavaScript
            const value = useMemo(() => ({ user, login, logout }), [user]);
            return <AuthContext.Provider value={value}>{children}</AuthContext.Provider>;

৫.  Context API vs Redux / Zustand (কখন কোনটা ব্যবহার করব?)
    ইন্টারভিউতে অবশ্যই এই প্রশ্নটির সম্মুখীন হতে হবে:
    0.  বৈশিষ্ট্য
        Context API,Redux Toolkit / Zustand

    1.  Setup & Complexity
        "খুব সহজ, কোনো থার্ড-পার্টি লাইব্রেরি লাগে না।",কিছুটা সেটআপ ও শেখার প্রয়োজন পড়ে।

    2.  Re-render Optimization
        ডেটা চেঞ্জ হলে সব Subscribed Component রেন্ডার হয়।,Selector-এর সাহায্যে শুধু নির্দিষ্ট প্রপার্টি চেঞ্জে রেন্ডার হয়।

    3.  Best Used For
        "লো-ফ্রিকোয়েন্সি আপডেট ডেটা (Theme, Auth Status, Language)।","হাই-ফ্রিকোয়েন্সি ও জটিল ডেটা (E-commerce Cart, Live Dashboard, Large Form)।"

৬.  ইন্টারভিউ প্রশ্ন ও স্মার্ট উত্তর (Interview Q&A)
    ১.  useContext ব্যবহারের সময় "Cannot read properties of undefined" বা Null Error এড়ানোর উপায় কী?
        উত্তর:

        Context ব্যবহারের জন্য একটি Custom Hook তৈরি করে তার ভেতরে চেক করা উচিত যে useContext(MyContext) থেকে প্রাপ্ত মান undefined বা null কি না। যদি null হয়, তবে একটি পরিষ্কার Error Throw করা উচিত—যেমন: "useAuth must be used within an AuthProvider"। এতে ডেভেলপারের ভুল ধরতে সুবিধা হয়।

    2.  useContext সম্পর্কে ইংলিশে কীভাবে বলবে?
        "useContext is a React Hook that consumes values from a React Context directly within functional components, effectively solving the prop drilling issue.

        It's ideal for sharing low-frequency global state like themes or authentication. However, since any value change in the Context Provider triggers a re-render for all subscribing components, I follow best practices such as splitting contexts by concern and memoizing the provider value with useMemo for optimal performance."
